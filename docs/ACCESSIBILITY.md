# 可访问性与低动效策略

原文先出现，读者主动决定何时看译文。这是阅读交互，不应阻挡键盘、屏幕阅读器或视觉障碍用户。

- 交互控件采用原生button、input，不用只有鼠标可用的div点击。
- 独立译意控制器使用aria-expanded false/true与aria-controls id。译意初始hidden，从可访问树与视觉布局中同时隐藏。
- Tab可顺次焦点到每条句卡按钮；Enter/Space可打开。字号、收藏、主题和上一/下一篇也可键盘操作。
- 搜索结果数量、展开计数与轻提示使用role=status和aria-live。
- 键盘/可聚焦搜索框不抢夺其他输入控件；正文允许常规文本选中。
- 主体颜色保证暗明两种对比，focus-visible焦点明显。
- prefers-reduced-motion禁用日轮浮动及滚入过渡。不应因此让标题正文仍保持opacity=0。
- 手机320–430px无横向翻译栏，原文和对应译文始终按阅读顺序上下排布。

自动化只能检查DOM约束；屏幕阅读器宣读顺序、缩放至200%以及小屏的真实使用必须单独人工测试。
